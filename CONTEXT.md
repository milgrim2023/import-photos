# Project: ImportPhotos

A macOS-native utility for high-integrity media ingestion from SD cards to local storage. It only ever **copies**. v1.0.0 is built; see `.scratch/import-engine/PRD.md` for requirements and `README.md` for the repo map.

## Glossary
- **Source / source roots**: what the user picked in the system panel. One folder = browse it; files or several items = import those.
- **Destination**: the folder photos are copied into. Its whole tree is scanned for duplicates.
- **Photo**: any non-sidecar file that gets imported (images, RAW, video).
- **Sidecar**: a companion file named after a photo (`IMG.xmp` or `IMG.ARW.xmp`). Written by Adobe/darktable/Photo Mechanic (`xmp`), RawTherapee/ART (`pp3 pp2 arp`), DxO (`dop`), Capture One (`cos`), Canon DPP (`vrd dr4`), Canon/GoPro (`thm`), Apple Photos (`aae`), ON1 (`on1`), UFRaw, Exiv2/ExifTool (`exv mie`), and `rrdata`. The single list is `SidecarNaming.extensions`; generic types (`xml json txt`) and playable proxies (`lrv`) are deliberately excluded.
- **Template**: the destination layout string, e.g. `{{YEAR}}/{{MONTH}}/{{NAME}}`.
- **Time offset**: a correction applied to each photo's timestamp for path *and* duplicate check.
- **Duplicate**: same **Name + Timestamp (offset-adjusted) + Size** as a file already in the destination. A file is never a duplicate of itself.
- **Renamed**: a name collision that is not a duplicate; imported with `_1`, `_2`… suffix.

## Core Logic

### Media Ingestion & De-duplication
- **Purpose**: import a chosen subset of files from an SD card to a destination folder.
- **Selection**: whole volume, folders (recursive), or individual files.
- **Timestamp priority**: EXIF/metadata (ImageIO for images/RAW, AVFoundation for video), else file modification date.
- **Time offset**: optional, resets each launch. Destination files are assumed to already be corrected, so the adjusted incoming timestamp is compared against the stored destination timestamp.

### Organization
- **Structure**: the Template string, evaluated on the offset-adjusted timestamp. Remembered across launches.
- **Media support**: major image formats incl. RAW, and video (`.mp4`, `.mov`).

### Sidecars
- **Never shown, never selected**: the UI lists photos and folders only. Sidecars are copied **implicitly** with their photo (into its folder, under its final possibly-renamed name) and only counted in the results.
- **Never imported alone**: orphan sidecars (no photo) are ignored, but **listed in the results**.
- **Existing wins**: a sidecar already in the destination is never replaced or duplicated; a photo skipped as a duplicate never brings its (possibly newer) sidecar.
- **Both naming styles**: `IMG.xmp` and `IMG.ARW.xmp`.
- **Sandbox caveat**: picking individual photos in the panel doesn't grant access to their folder, so their sidecars can't be found unless picked too; the UI warns.

### Cancelling
- **Between files only**: Cancel stops before the next file. The file in flight completes (media + sidecars together) and is shielded from the cancellation. Unreached files are reported as *cancelled* (not imported). Imported files are kept.

### Sorting
- Default: file date, oldest first, folders on top. **Capture date** sorts read EXIF/video dates lazily (once per file, cached; file date used until loaded; ADR-0006).

### Failures
- **Per file**: one unreadable file is reported as Failed and the import continues. A failed file leaves nothing behind in the destination (media + sidecars are staged then moved together).

## Tech Stack
- **Language**: Swift 5 (language mode), tools 5.9. **UI**: SwiftUI + `Observation`. AppKit for `NSOpenPanel`. QuickLook (`quickLookPreview`) and QuickLookThumbnailing for previews/thumbnails.
- **Metadata**: ImageIO (images/RAW) & AVFoundation (video). **Concurrency**: Swift Concurrency.
- **Packaging**: logic + views in the SwiftPM library `ImportPhotos`; the app target (`App/`) is generated by XcodeGen from `project.yml`.
- **Tests**: XCTest, real temp-dir filesystem, fakes only at the system boundary (open panel/bookmark store). Views are "humble": decisions live in `Presentation.swift` and the view models. An XCUITest smoke suite (`UITests/`) drives the real app via a Debug-only test mode (ADR-0004).

## Technical Constraints & Environment
- **Platform**: macOS 14+, **Apple Silicon only** (arm64). No Intel code is generated.
- **Sandbox**: App Sandbox, `user-selected.read-write`, `bookmarks.app-scope`. Chosen sources/destination persist as security-scoped bookmarks (ADR-0001).
- **Signing**: ad-hoc, no Apple Developer account (ADR-0003).
- **Large transfers**: handled by streaming file copies off the main actor; overhead is linear in file count.
